### 개요
sqlitem은 터미널에서 SQLite 데이터베이스의 스키마를 항사 눈에 눈 채로 SQL을 작성, 실행하고, 결과 그리드에서 데이터를 직ㄱ접 수정할 수 있는 단일 바이너리 도구

주사용자
- SSH로 접속한 리눅스/맥 서버에서 SQLite 파일을 직접 확인, 수정해야하는 개발자, 운영자

전체 역량
- SQL을 직접 작성할 수 있고, vi 키 바인딩에 익숙하거나 익술해질 의향이 있는 사용자

사용 환경
- 느린 SSH 링크, Unicode 렌더링이 불안정할 수 있는 터미널, 설치 권한이 제한된 서버

### 제품원칙

순수 Go SQLite 드라이버 사용 (modernc.org/sqlite)

좌측 패널에 스키마는 항상 보이도록 함키 입력당 전체 재 그리기를 하지 않음, 라인 diff + 프레임 코얼레싱 기반 랜더링 유지

터미널의 기본 동작을 빼앗지 않음 - 마우스 캡처를 켜지 않아 터미널 네이티브 선택, 우클릭 복사가 항상 동작

데이터 변경은 흔적을 남김 - 모든 쓰기 작업은 before/after 와 함께 JSON 로그로 기록

파괴적 동작은 반드시 확인 : UPDATE/DELETE는 확인 모달 없이 실행되지 않도록 함

### 실행 모드

DB 파일 경로는 필수, -db 플래그 또는 첫 번째 위치 인자로 받음, 파일이 없으면 새로 생성

sqlitem <file.db>
sqlite -db <file.db>

콘솔 REPL : -console : 라인 기반 REPL, 파이프/스크립트용, TTY 불필요
단발 실행 : -exec "<sql>", -query "<sql>" : SQL 실행 후 종료, TTY 불필요
ASCII 모드 : -ascii : ASCII 테이블 렌더링, TTY 불필요, Unicode 미지원 터미널용

### TUI 레이아웃
좌측 Schema
우측 : 상단 SQL, 하단 Result Grid
 - 그리드 맨 앞에는 1부터 시작하는 일련번호('#') 컬럼 추가, 랜더 전용이며 데이터 좌표에 영향을 주지 않음

포커스된 패널은 테두리, 제목이 밝게 강조되고 제목 앞에 * 표시, 포커스 이동은 Tab/Shift+Tab, Ctrl+Tab, Ctrl+Shift+Tab

구현 : tui.go (로트 모델, View 합성), tree.go, editor.go, grid.go, modals.go

### Schema 패널
테이블과 뷰 목록을 2단 트리로 표시, 펼치면 각 컬럼의 타입과 PK/NN 등 표시가 보임
시작시 테이블이 10개 미만이면 전부 펼친 상태로 보이게 함, 10개 이상이면 접힌 상태로 표시
이동은 펼처진 노드를 평탄화한 목록 위에서 선형으로 동작, 테이블의 마지막 컬럼에서 'j'를 누러면 자연히 다음 테이블로 이동
테이블에서 Enter를 누르면 "SELECT * FROM <table> LIMIT 100;" 스타터 쿼리를 편집기에 채우고 편집기로 포커스 이동
v로 선택 테이블의 DDL, 'V'로 전체 DDL을 팝업으로 보여줌
DDL에는 관련 객체 (인덱스, 트리거 등)가 함께 표시'
'y'로 선택한 테이블명 또는 컬럼명을 클립보드에 복사
CREATE/DROP/ALTER는 실행시 스키마 트리를 즉시 갱신
트리 형태로 구성, /를 통해 검색 기능 추


키 바인딩
 - j, k, 아래 화살표, 위 화살표 : 상하 이동
 - l, 오른쪽 방향 화살표 : 닫혀 있으면 펼치기, 펼쳐져 있으면 첫 컬럼으로 진입
 - h, 왼쪽 방향 화살표 : 컬럼이면 테이블로 이동, 테이블이면 접기
 - gg, G+End, Home : 맨 위/맨 아래 이동
 - Enter : 스타터 쿼리 편집기 채우기
 - y : 이름 복사
 - v, V : DDL 보기


### SQL 편집기
여러 줄 SQL을 작성할 수 있고, ';'로 여러 문장을 구분가능
기본 모드는 INSERT (일반 타이핑)
Esc로 NORMAL 모드로 전환
현재 모드는 패널 제목에 표시

undo 스택을 유지하며, u로 되돌림
Control-F로 SQL을 포멧팅함
VISUAL 선택 범위는 하이라이트로 표시


실행
F5, Ctrl+R 편집기 전체 내용 실행
F3, Ctrl+K 커서가 위치한 문장만 실행
읽기 쿼리 


### Result Grid
모든 좌표는 res.Rows, res.Columns 에 대한 0-based 인덱스임
결과가 0행이면 모든 이동이 구조적으로 no-op ('i' 삽입만 유효하게 유지)
컬럼 폭은 결과로 캐시
VISUAL 블록 선택 (행, 열 2차눤 범위) 지원, 선택 영역은 하이라이트로 표시

키바인딩
 - h, j, k, l : 방향키, 셀단위 이동
 - PgUp / PgDn : 20행 단위 이동
 - gg, G+End, Home : 행 이동
 - q, Enter, Esc 닫기

### 데이터 편집
편집 기능은 rowid 기반으로 동작

인파인 편집은 단일 테이블 SELECT 결과에서만 가능
QueryEditable이 대상 테이블을 감지해 <table>.rowid를 앞에 붙여 재실행, 합성 컬럼은 화면에서 숨기며 각 행의 rowid를 보관
수정은 rowid 기반으로 실행, PK가 없어도 정확히 해당 행만 갱신
컬럼단위 안전장치 : 실제 테이블 컴럼만 수정 가능, count(*), 표현식 등 계산 컬럼은 읽기 전용
편집불가(JOIN, 서브쿼리, 집계, 표현식 컬럼뷰 등)의 경우 상태바에 사유를 표시하고 편집 키를 무시
셀 편집 모달에서 'Set NULL' 체크로 NULL을 저장할 수 있음
수정은 편집 before/after 확인 후 적용의 다단계 흐름을 거치도록 함
삭제는 삭제 재확인을 거침
다단계 흐름에서 Cancel시 이전 모달로 복귀 (이전 모달을 클로저에 보관)
변경 결과는 그리드와 상태바에 즉시 반영
모든 DB 접근은 db.go를 경우, UI는 직접 커넥션을 열지 않도록 함
